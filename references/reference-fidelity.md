# 参考还原与动画检查

用于已有项目的三维迁移、用户指出“像示意但不像原作”、或要求优化运动与配色。以下是双案例 V2 的执行经验，不是原作者的提示词或外部库依赖。

不同题材的构造重点见 [题材方法](subject-workflows.md)；对照和返修的阶段判断见 [视觉验收](visual-acceptance.md)。以下具体源公式、发动机阶段与配色只适用于对应源，不当作所有主题的默认建模规则。

## 1. 做一张可核验的特征表

每行记录 `参考特征 | 源文件/函数/版本 | 原始数据或重新建模 | 对应模块 | 验收画面/状态 | 剩余差异`。

至少覆盖：主体轮廓与比例、接口/支架、管路截面、重复构件、关键功能近景、色彩分工、启动/运行/停机。按这些特征分配细节，不用增加无关螺丝来掩盖整体比例错误。保留用户参考与改编截图，不能把自己生成的图当原作。

Raptor 的具体源包括 `examples/raptor-engine/build.mjs` 的回转轮廓、法兰参数和管路记录，以及 `live.js` 的拆解错峰、弹簧和燃烧阶段。涂装车间的 `robotSvg` 包含肩部、上臂、肘部、前臂、腕部和工具的实体尺寸；只迁移 `robotPose/fk` 再画几根杆，不算恢复机器人外观。源与固定 SHA 见 [来源映射](source-map.md)。

## 2. 先对齐投影，再调比例

从源代码确认世界坐标、up 轴、投影和观察方向。某些 SVG 等轴投影具有与目标引擎不同的平面手性；仅复制相机角度可能看到另一面。

本次源投影为：

```
screenX = (x*sin(A) - y*cos(A))*k
screenY = ((x*cos(A) + y*sin(A))*sin(E) - z*cos(E))*k
```

在 Z-up Three.js 中，对这套公式采用模型 `scale.y = -1`，相机方向 `[cos(A), -sin(A), tan(E)]`。**这不是任意模型的通用修正**；先用至少四个不共面的源点与实际 camera 矩阵投影比较。标签、点选代理、聚焦目标也必须使用同一转换；反射后核对正反面、法线和背面渲染。

锁定相机、画幅和装配状态，比较总览；再放大关键工位或接口。整体构图、空隙、轮廓和近景细节分别验收。

`source-frame.js` 的 `factoryProjectionFrame(A,E)` 只实现上述源公式，返回统一根变换和相机方向。不要在子构件再反射；标签和聚焦点经 `root.localToWorld()` 转换。`checkProjectionLandmarks()` 使用实际 root/camera 矩阵与至少四个不共面源点检查像素误差；期望屏幕位置必须来自独立源公式或实测，不能再由被检查相机生成。刻意移除反射时应失败。它只核对投影配准，不证明模型形体准确。

## 3. 保留能解释结构的细节

- 回转件保留截面；管路记录含变径数组时按长度插值生成截面，不能默默取平均。开放喷管必须有内壁和出口。
- 法兰螺栓、支架接缝、刻度、线槽可能只存在于 SVG 线画层，审计记录中没有它们。逐项查源声明，补建真实几何，并区分参数继承与手工重建。
- 机械臂的壳体与工具用原姿态统一驱动，不能让精细壳体留在旧姿势。随车旋转的吊具也应用车身局部旋转，不能只有平移。
- 重复构件可实例化；轮廓线必须复用相同 instance matrix 与实际 count，避免旧线框留影或无效实例堆在原点。

## 4. 配色按最终画面校准

参考为白灰技术图时，先去掉环境光和补光的色偏，再调整材质。保留炉体橙色、槽液/玻璃浅蓝、车身状态色等语义；不要因使用了相同 hex 就宣称颜色一致。色调映射、曝光、金属度和透明叠加都会改变结果。

在同机位实际截图中核对大面积白灰、强调色和边线。阴影应帮助辨认结构；过重的楼板投影会吞掉下层细节。改变灯光后重新检查近景和背面。

## 5. 动画应有转换条件

列出状态表与可见效果，再实现纯状态函数。可采用 `合拢等待 → 吹扫 → 预燃 → 主燃 → 稳态 → 停机余烟 → 冷态`；这些是案例的表达方式，其他设备应按自己的来源定义。

分别保存目标与实际位置。错峰与弹簧逐部件积分、限制 dt、必要时子步进；所有部件实际归位后才启动燃烧时钟。暂停冻结统一时间，包括噪声和余烟；从暂停态按停机应能正常执行停机。复位清理残余速度和效果；reduced-motion 可直接到装配目标。

体积喷流可用世界空间 raymarch 或真实粒子体积，不能用一个不透明圆锥/球体替代原作云状效果。透明包围盒背面参与深度测试时，平台可能把整片烟雾裁成硬三角形；检查实际射线入口与实体遮挡，采用合适的入口面/场景深度截断或有明确边界的解析遮挡。不要用关闭所有深度测试掩盖问题。

## 6. 验收与证据

1. 纯状态：冷态、半拆、全拆、错峰、中途反转、启动等待、各阶段、暂停、停机尾迹、复位；检验有限数与周期边界。
2. 浏览器：实际操作对应按钮，观察状态与画面同步；保存总览、拆解、燃烧、背面和功能近景。纯状态测试不能证明 shader 已编译或透明遮挡正确。
3. 保留版本：V1 与 V2 观察值、截图和断言分开；旧记录不能当成新代码的执行证据。修复后重验受影响流程，避免无目的反复测试。
4. 报告还原边界：本次三维重建不等于逐像素一致或工程级复原；静态 SVG 的完整三维资产缺失时明确列出重建部分。
