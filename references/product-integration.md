# 产品建模的实际接入与验收

用于参考产品的材质、贴附与细节组织；不为静态外观任务自动增加机构和拆解要求。

## 参数、几何与附件

参考标注值与制作参数分开保存。轴距、轮轴、外壳边界或窗洞用共同的数据源驱动关联几何；不能各写一套近似坐标。分片面板共享边界，附件用 `surfaceFrame/placeOnSurface` 跟随曲面；仍需看高光、轮廓和连接。局部曲面拼合与完整参考复刻分别验收。

`mesh-anchors.js` 提供 `auditMeshAnchors(root, checks)`；每项 `{id,a:{mesh,vertex,instance?},b:{mesh,vertex,instance?},expectedDistance,tolerance}`。锚点必须是显示树中实际被索引的顶点，期望间距来自设计接合/参考，不从测量结果反填。拓扑修改后重选顶点；检查器不会判断你选的顶点是否有语义意义。`buildScene()` 返回 `meshAnchorChecks` 时，场景与网页检查会读取同一实际对象。无规则返回 unconfigured，不算连接通过。

使用实际孔/面探针检查接口时继续复用 `assembly.js`。针对关键关系做一个独立副本反例：把实际窗、灯壳、支座或附件移开而保持规则不变，检查必须失败。有限数、复位和幂等通过不证明接合正确。

曲面接缝不能只查一个角点：至少覆盖端点与有曲率的中段，并在斜视图看是否漏光。共享边界位置只能约束接合；高光是否连续还取决于切向/法向。单顶点间距通过不能表述为整条接缝或整个车身连续性通过。跨拆解部件的约束应在装配姿态检查；始终一起运动的同部件锚点可随姿态检查。

## 材质与照明必须作用于交付物

`productMaterials({textures:true})` 返回 `{materials,maps,dispose}`；包括车漆、碳纤维、橡胶、金属、玻璃与灯罩的可调整起点。`surfaceMaps(kind,{size,repeat,seed})` 支持 carbon/rubber/brushed/grain，返回分别标明 sRGB 颜色与 NoColorSpace 数据的贴图。它们是程序材料示意，不是实测材质。先按可见尺度调整 UV 与 repeat，再决定是否需要微纹理；不要把同一噪声贴到所有材料。

`studioEnvironment(renderer)` 返回带 PMREM 的 `{texture,intensity,dispose}`。可在 `configurePresentation` 中赋给 scene.environment；场景退出时由调用方释放。根据对象和参考控制反射、粗糙度与光源尺寸，灰模与最终材质都要看。透明与折射不是同一功能；轮廓/开口不能用透明材质或凹凸贴图替代。

可传入 `{background:'#151820'}` 调整环境暗部；默认保持原有中灰背景。它改变反射对比，不改变模型曲率。碳纤维等非金属在掠射角也可能反射成亮板，按参考调整材质 `envMapIntensity`、粗糙度与清漆，先用实际网格命中检查确认亮区不是缺面。

实际浏览器回读需检查：预期材质已绑定到可见网格、贴图可用、颜色/数据色彩空间正确、字体与数字朝向正确；背面贴花不能因对称复制而镜像。检查默认首屏与近景，单独的材质小样不能代表模型已完成接入。

网页提供只读 `__wireframe.appearance()`，回读当前可见网格实际绑定的材质、贴图尺寸/色彩空间和环境名称；应在所需显示模式下取样，不能把灰模回读当作最终材质。

透明贴花标记 `userData.isSurfaceDecal=true` 和 `auditIgnore=true`；灰模时由预览隐藏其绘制，再恢复原材质，避免胎壁/标志变成不透明方片。贴花属于显示辅件，不能承担轮廓、孔或尺寸测量。`mountIllustration` 会保留接入后的 studio 背景与色调映射。

## 静态合批的边界

`batchStaticChildren(group,{keep:[]})` 只合并一个语义组的直接、兼容、不透明静态子网格；不会跨层级合并。保留组以支持选择/隐藏/拆装。动画对象、被测几何、关键点引用与独立可选零件放入 keep，或标记 `userData.keepSeparate/auditTarget/referenceProbe/dynamicGeometry`。在建立 runtime 的 rest pose 前调用。合并后返回 `batches/removedMeshes/skipped`，不释放原几何，因为其他实例可能仍引用它。

需要逐件选择、实例化、透明排序、蒙皮/morph 或独立运动的对象不合并。合并后实际核对世界几何、材质、阴影、选择、展开及测量；只看到 draw calls 下降不算成功。动态场景不照搬静态阴影缓存；记录测量条件下的帧时间，不能凭三角形数报告 FPS。

## 用案例检验改进

保留原始输入、固定技能版本、实际代码与检查。灰模看比例/轮廓/负空间，材质图看受光与材料区别，局部看连接和开口，最终重开入口。记录最明显的问题、模型原因、修改和同条件结果；明确遗留差异。当前用户给定的汽车可作为开发与回归任务；没有独立新输入时不声称泛化提升或盲测通过。扩展到新题材所需的结构与场地能力另行实现，不把本页产品方法视为已经补齐建筑/植被系统。

修改以上模块后运行 `node scripts/verify_product_tools.mjs --three <three目录> --report <JSON>`。该检查覆盖色彩空间、实际材质绑定、合批前后世界坐标/法向、保留对象、实际顶点反例和灰模贴花恢复；PMREM、shader、相机与交互仍需真实浏览器验证。汽车开发例保留了多次返修截图，但没有旧版 skill 同任务独立运行的 A/B 对照，因此只能报告新增能力与本次返修效果，不能报告因果提升百分比。
