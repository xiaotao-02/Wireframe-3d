# 迁移已有 Anatomy 作品

用于用户指定某个开源案例的三维改编。以下来自 Raptor 与三层涂装车间的实际测试，不是上游作者通用提示词。

## 先区分记录的用途

核对源文件与固定版本，把可恢复内容分成显示几何、审计代理、语义布局和状态函数。`kit/audit.mjs` 的几何记录可能是碰撞包络；不能因为名称是 nozzle 就直接当成空心喷管。

在参考特征表中标出每份记录的用途及其调用点：`显示几何 / 审计或点选代理 / 线画细节 / 姿态 / 外层门控`。无法确定的记录标为待确认，先比对原作管口、截面或工作空间，不静默按实体导入。代理留作辅助时标记 `auditRole:'proxy'`；真实网格检查只指向实际装配树，不能另建一套完美的审计场景。

Raptor 的 `examples/raptor-engine/build.mjs` 可执行并截取 `R.solids/R.tubes`；排除实心 bell 审计代理，用源半径函数生成带壁厚回转网格。静态线条细节不一定进入审计记录，需要逐项从源声明补建。管路用平均半径或少截面简化时在交付说明记录。

V2 已保留管路变径数组并补建法兰螺栓、立柱连接、线槽和平台刻度。验收：看喷管口与背面，检查轴向变换的基向量和手性；抽查 `rest + amount * move` 在 0、0.5、1 的位置。显示为空心不等于已完成全面拓扑审计。

## 独立提取状态，再接渲染

涂装页公开 `DATA` 与 `bodyState/computeEntities/robotPose/fk`，但已烘焙静态 SVG 并不等于公开完整三维资产。保留前者，按其坐标重建后者，明确区分继承代码与重新建模。

提取纯函数时核对依赖闭包，包含角度常量、插值、向量运算、颜色状态和调度表；先独立执行完整循环，再绑定 Three.js。使用原调度 ID 连接车身、工位与机械臂，不按显示顺序关联。

动态显示构造同样是来源：V2 从 `robotSvg` 的实体尺寸恢复关节外壳与工具，用 `robotPose/fk` 驱动；RoDip 吊具随车身旋转。只继承运动点位并不等于外形已还原。视角、配色与效果问题按 [参考还原与动画检查](reference-fidelity.md) 验收。

五车间补充见 [原显示代码与设备恢复](source-render-porting.md)：迁移矩形臂段的截面参考轴；外层门控、独立 AGV 时钟和托盘相位也是依赖闭包的一部分。静态参考重建与直接迁移的显示函数分别记录，不用工位数量宣称外形已完整恢复。

验收：逐时间点检查有限数；按源定义核验升降范围与机械臂骨段长度；周期首尾比较。它们证明状态一致性，不证明工业流程或避碰正确。

## 复杂场景的观察与成本

同材质静态几何按语义组合并，重复车身/输送辊/机械臂用实例化。保留语义选中代理，选中代理不能算作生产设备。实例化统计区分 prototype 三角数、实例展开数和含阴影的 draw 统计。

楼层展开后暂停跨层流转；完整取景应随展开范围变化。窄屏按整个场景包围范围调整正交视野，限制标签越界。隐藏部件只能称独立查看，只有镜头实际跟随才称聚焦。

页面隐藏时 RAF 通常停止；验收截图先确认目标页前台且已绘制。不要只根据控件新值和旧画面宣称通过。截图、窗口切换和后台恢复会污染帧时，性能结论需单独测量。

按原作逐类验收静态机器：不同工具、开口、载荷空间与壳体需要不同构造。复用八类设备到上百个工位可以作为明确的示意选择，但不能据工位数量称逐台还原。关键几何缺失时先补构造；剩余简化具体记在特征表，不隐藏在“全部检查通过”后面。
