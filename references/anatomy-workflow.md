# 从 Anatomy 迁移的制作方法

用于新题材、参考还原或技能自身迭代。先选任务需要的部分，不把所有规范变成每次必交的表单。精确来源见 [source-map.md](source-map.md)。

## 先确定读者要看懂的因果

写一句“操作 X → 构件 Y 改变 → 结果 Z”，再选能让这个关系直接可见的结构。例如按钮下移、桥接触点、灯丝亮起。给真实对象还原时，保留其原有构造；解释抽象概念时可以创造机械隐喻，但明确隐喻与真实机制的边界。

在当前项目保留一份紧凑制作记录，已有部件表可直接补列：

`对象/问题 → 可观察机制 → 关键构件与接口 → 依据/推测 → 判定方式`

先明确“属于谁、接到谁、什么条件下改变”。沿一条主要路径把输入、传递与输出串起来，标出分支、断点及不可见部分，再决定用局部剖切、展开、强调色或引线。展开只解决空间遮挡，不能自动解释能量/物料/运动的传递；全透明也不保证关系可读。

标注锚点绑定语义部件及其实际局部坐标，跟随装配和运动；隐藏或独显时同步筛选标注。验收时沿路径逐段检查：起点、连接、方向、终点是否看得见，是否能解释当前状态的结果。机构原理与工艺顺序须另查来源或计算依据；纯状态测试和漂亮画面都不能证明科学正确性，缺少依据的部分明确标为示意/推测。

挑出最能决定质量的轮廓、负空间、连接或工况。先完成一个可验收的局部，例如一组法兰、导套或工位，再扩展同类结构；别先铺满全场的占位盒。

## 把“精细”落在有作用的构造上

| 看到的部位 | 建模时落实 | 检查证据 |
|---|---|---|
| 底板、滑台 | 厚度、槽口、导轨、限位与安装座 | 侧面/近景；实际表面与行程 |
| 杆与壳体 | 连续的一根杆、真实穿孔、导套与同轴 | 孔探针、极限姿态、背视图 |
| 管线与端子 | 端点从接口生成；弯曲半径与过渡留距 | 接口配合、真实端面、路线与障碍物间隙 |
| 旋钮、仪表 | 滚花、刻度承载面、轴心和固定方式 | 近景；指针与同源读数 |
| 盖板、板缝 | 实际分件边界、螺孔/紧固件、合理止口 | 装配与展开两态，不用线条假装洞口 |
| 建筑与工厂 | 洞口、支承、机架、转运接点与设备外形 | 平/侧视和关键工位；同一流程状态 |

细节数量服从实际对象和观看尺度。重要轮廓用真实几何；反复小件可以实例化；远处细缝可以轻线表达。装饰线要落在真实边界或承载面上。不要为凑面数生成螺钉，不把每个零件随机涂成不同颜色。

曲线端点正确仍可能在中途穿底板：Catmull-Rom 会在控制点之间偏离折线。补过渡控制点，并针对实际扫掠网格与底板检查净距；不能只验两端坐标。`contact-switch` 曾在截图中暴露此问题，现在同时检查六个端面与三条导线对底板的间隙。

## 将状态、几何、读数接成一条路径

网页默认使用 `motion.js → scene-runtime.js → setPose()`。`setPose` 读取实际归一行程，不读取滑块目标；返回的 `phase/readout` 同时呈现在界面与检查报告。粒子/噪声/灯光也只使用传入的时钟或确定性种子。

`createSceneRuntime` 每次先恢复根节点及已有子节点的 position/quaternion/scale/visible，再调用 `setPose`，最后施加部件展开位移与拆解隐藏。这个顺序避免绝对位置赋值覆盖展开。不要在运行中不断创建新的运动节点；顶点变形、材质变化及随状态改变的可见性仍需 `setPose` 显式、可重复地设置。它不能替任意黑盒动画消除内部副作用。

运动启停、语义状态表、完整播放与截图回放见 [motion-and-verification.md](motion-and-verification.md)。多阶段点火或工艺不能硬塞成单一 stroke：可以扩展纯状态模型，保留同一时钟与真实姿态驱动的原则。

## 保持共同画风，同时验收新的对象

结构科普且未指定参考风格时，使用 [illustration-style.md](illustration-style.md) 的纸面、浅灰体积、细轮廓、局部语义强调色。Wireframe-3d 的名字不意味着打开三角网格线框。参考建模按 [参考建模与首次交付](reference-reconstruction.md) 决定材质与呈现；保留机构语义不要求同时采用插画画风。

对照原作时分三层：

1. 机制：动作与结果是否一致，读数是否对应实际运动。
2. 构造：主体比例、负空间、端接、开口和承托是否有来源且合理。
3. 画面：相同投影/画幅/状态下，明暗、线条层次、密度、留白和强调色是否协调。

上游 SVG 的 painter order、把曲面拆片以排序、轮廓细分策略不直接搬进 Three.js。这里用真实深度、实体网格、受控法线与屏幕尺度描边；背面和自由视角也要成立。用户要求复刻时，以用户参考为准，不继承上游“必须原创对象”的限制。

## 用新题目检验技能

`evals/evals.json` 保存独立任务提示与可观察的通过条件；不是已通过案例列表。选择与本次改动相关且没有靠历史成品直接作答的题，在独立输出目录完成。记录输入、所用技能版本、产物、实际执行检查、视觉差异与未验证项。当前 `contact-switch` 是开发验证例，不冒充独立盲测。

不要只验证“文档里出现了某句话”。让错误实际发生：错移端子、缩小真实孔、让管线穿板，确认对应检查会失败。脚本通过后仍打开截图；只为当前可见失败补必要规则，避免每次加一整套通用流程。
