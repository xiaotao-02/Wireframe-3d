# 质量回归

用于用户给出旧版、要求返修不退步，或评估 skill 改动。小范围改动只检查受影响项；不为普通建模自动创建大型评测流程。

## 固定比较依据

保存用户输入、实际提示词、模型/推理档位、技能快照与依赖版本。新会话从原始材料生成，不把旧工程复制为“新 skill 生成”；若任务本来是修旧工程，则明确记录这一点。旧结果经过多少轮反馈、是否有额外参考图，也属于条件差异。

| 项目 | 看什么 |
| --- | --- |
| 主体 | 轮廓、比例、负空间、关键识别部位 |
| 表面与接合 | 灰模中的折面、尖刺、裂缝、穿插；孔口与附件连接 |
| 呈现 | 关键材质可辨、色块/文字方向、默认取景与近景 |
| 所需功能 | 原有拆装/选择/动作、暂停、复位、输出是否保留 |

每项用“改善 / 相当 / 退步 / 未核验”，对应实际截图或动作证据，不计算没有依据的综合分。未配准图片不作逐像素指标；尺寸数值不能替代轮廓判断。

## 验证生成结果

用同一引擎、视口、显示模式、装配状态和可比相机观察新旧作品；先灰模，再最终材质。检查默认视图和容易暴露缺陷的侧后/局部视图。几何运算须在输出网格上验证：操作前后的作用区域、三角面面积、接缝位置与朝向。正常设计开口与意外裂缝分别判断。

发现回退时先定位几何表示、局部运算、材质还是呈现问题。只修证据支持的原因；不要把该案例的车型参数、修补公式或固定构件数写成通用技能要求。修后重新生成并复看，不沿用旧截图。后续给模型的返修反馈另存，不能把多轮修复称作首轮成功。

## 判断是否可以发布

用户要求“不低于旧版”时，关键主体/表面与必要功能不得有未解决的退步。检查通过但画面明显损坏，仍不满足要求；缺少可比产物则保持未核验。只发布实际验证覆盖的结论，不用开发例或故障注入代替同题生成。

技能试验使用隔离目录保存输入、技能哈希、mcode 会话/模型记录、产物、截图与结论。案例含用户素材时，不随技能仓库公开这些素材；仓库可以保留通用方法和不含私人材料的验证说明。
