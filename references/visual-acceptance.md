# 视觉对照与返修

用于复刻、跨题材建模或用户反馈“能运行但不像/不好看”。只改按钮等小 UI 时，不强制重跑整套模型检查。

给图建模的首次制作也执行本页；制作前先读 [参考建模与首次交付](reference-reconstruction.md)。阶段检查由执行者在同一次请求内完成，不必等待用户逐轮指出形体问题。

## 先固定要交付什么、给谁看

将用户的要求整理为“必须出现 / 必须保持 / 禁止出现 / 交付格式”，保留原意与来源。另写一句默认画面要传达的主信息，记录目标载体、观看尺寸、默认状态；定长演示还记录关键镜头停留时间。未指定的普通呈现选择可自行确定并说明，不能把自己的偏好冒充用户硬要求。

可从 [制作与交付检查记录](../assets/templates/quality-review.md) 复制需要的部分到项目 `evidence/quality-review.md`，或补充已有记录。不复制空表作为完成证明；不适用的检查说明原因，不强迫静态展示增加动画、剖切或导出路线。

## 制作阶段检查

| 阶段 | 比较什么 | 发现问题后改什么 |
|---|---|---|
| 白模轮廓 | 同视角的整体比例、负空间、体量错落、支撑落点；去掉纹理、特效和 UI 后的辨识度 | 修轮廓、尺寸和布局，先不增加装饰；不依靠涂装或标题让主体“像” |
| 主体曲面与识别特征 | 受光灰模的曲率、面板边界，以及关键部位的轮廓/位置/深度 | 表达能力不足时换几何方法；灯具或开口仅“存在”不能算匹配 |
| 关键构造 | 用户关心部位的开口、壁厚、连接、轴心、窗框/工具 | 补真实几何；只检查运动点或代理盒不够 |
| 结构与因果（需要讲解时） | 能否从输入沿真实连接追到构件变化与结果；归属与流向是否有依据 | 先修部件关系与状态，再选局部剖切/展开/引线；单独核对机制来源 |
| 材质与光 | 基础照明和最终载体中各材料的差别、透明层次、亮暗部细节 | 先分材料与稳定照明，再加风格光；导出前后分别定位问题，见下文 |
| 展开与构图 | 装配/半拆/全拆、主体占比、标签及操作条遮挡；目标尺寸下能否读懂 | 改拆解向量、错峰或镜头；放大核心对象、减少次要正文，不靠无限放大底座填画面 |
| 动作与语义（有动画时） | 全流程中器具、操作、文案、数值与可见结果是否对应 | 修状态和转换条件，再修节奏；完整播放，关键抽帧只辅助定位 |

有图纸、原模型或明确参考时，保存可比较的参考视图与当前实际渲染；保持画幅、投影、主视角、装配状态和随机种子一致。自由视角效果也要检查背/侧面，不能仅让一个角度成立。只有截图时说明不可见面的推测；复杂项目可先选最能区分质量的少数特征，不以任意统一面数作为指标。

形体阶段查看相邻部件的接合：共享轮廓是否吻合，是否出现悬浮、重叠或无依据的缝隙。不要要求有意分件的接缝全部消失；以参考结构和装配关系为准。

## 在最终观看条件下检查

- **主信息与标注**：用实际目标尺寸、正常缩放打开默认入口，不先旋转、开专注模式或调试开关再验收。主体与关键说明应完整可见；标签跟随实际部件，隐藏部件不留误导性标签，引线不跨过关键结构。按关键镜头的停留时间正常播放，确认信息能读完；截图放大后可读不代表实际播放可读。具体 UI 检查见 [预览界面](preview-ui.md)。
- **材质与照明**：先在中性稳定照明下分清任务涉及的玻璃、金属、漆面、橡胶或织物等，再看风格光是否损失这些区别。检查玻璃后方是否仍有正确层次、亮部是否吞掉曲面/刻线、暗部是否吞掉孔腔。效果异常时分查材质分配/纹理与透明设置、照明/曝光，以及导出资源与查看器支持；不要只把场景整体调亮。
- **交付链**：有导出时对照原生工程、实际导出文件、目标查看器三处同一关键部件。记录差异最先出现在哪一处；网页渲染正常不能替代 GLB 导入检查，原生材质正常也不能替代目标查看器检查。只验证了其中一处，其余保持未验证；详细回读步骤见 [证据与交付](evidence-and-delivery.md)。

## 最小记录

在项目的证据目录记录，而非往技能里塞每次项目资料：

`特征 | 参考路径/视图/参数 | 当前实现 | 当前截图 | 判断 | 待修项`

判断使用 `匹配 / 有差异 / 未核验`。有明确尺寸的特征写容差及依据；审美差异用具体部位解释，不伪造相似度百分比。截图必须来自当前代码已绘制的页面，旧版本截图和 DOM 数字均不能代替画面。

出现以下问题时继续修正当前模型，而不是将其作为已还原交付：主体关键轮廓明显不符、核心构件被方盒替代、承力/连接明显断开、主要洞口封死、主体被 UI 或配景挡住。机制与动作表达错误、默认状态不可用、明确要求漏项也不能被漂亮画面抵消。可见范围仍不够或原资产缺失时列出具体差异，按用户允许的示意程度交付；不要用“技能验证通过”抹掉差异。

按影响主信息的程度返修：先处理主形体、结构关系和默认不可用，再处理材质层次、可读性与次要装饰。修复后在相同观看条件重验受影响的画面和状态，并回读默认入口。若问题来自同一构件生成器，修生成器并抽查其他尺寸，避免逐物体打补丁。不要把无限循环美化或严格逐像素一致设为所有任务的门槛。

## 两类结论必须分开

- 工程运行：脚本能运行、网格有限、动画状态正确、控件/窄屏可用。
- 视觉与还原：哪些参考特征对上，哪些仍有差异；图纸/原模型是否支持尺寸结论。

前者通过不能自动将后者标为通过。没有独立新题材结果时，报告构件和流程已增强，不报告“任意模型稳定高质量”。附带原创试件用于执行验证，不能冒充用户参考的复刻结果。
